# 推广执行手册（给用户与代理的可执行版）

> 状态日期：2026-10-05。配合 [matrix.md](matrix.md)（渠道总表）与 [gates.md](gates.md)（门禁）使用。
> 本手册回答一个问题：**没有用户反馈的现实下，怎么持续推进推广。**
> 分工原则：自动化（每日 12:00）负责 KPI 监测、素材产出、草稿箱；**人与代理只做"发布与回复"这两件需要真人身份的事**。

## 〇、现状诊断（为什么 45 下载/周却没有反馈）

goal.md 复盘已定位：**转化链断在「激活」**——有安装、零回流。类比成熟产品（Aider 靠 HN/Reddit 首发 + 文档 SEO；Cline 靠 marketplace 曝光 + YouTube 演示；AutoGPT 靠 GitHub Trending + 演示动图起量），共同点是：**先让人 60 秒内看到"它真的能用"，再谈其他**。所以我们缺的不是渠道，是**可看见的成功证据**和**能让用户开口的钩子**。

## 一、破局三招（P0，先于一切发帖）

### 1. 自证内容：把「成功交付」演出来（自动化 + 用户配合）

没有外部案例，就先制造**可验证的自我案例**：

- 选 3 个真实开源项目（如一个 Python CLI、一个 Node 服务、一个 Go 工具），用 DeliverKit 跑完整 deb/rpm/AppImage 流程，录成 **60 秒 GIF / 3 分钟视频**。
- 每个案例保留 `ReleaseManifest.json`（verified 状态）作为证据链——这正是项目「真实验证」铁律的最好广告。
- 产出物放 `docs/community/promotion/evidence/`，GIF 直接可用于所有渠道发帖。
- **给代理的任务卡**：录屏脚本已定（doctor → plan → pack-deb → 安装验证四步），用 [QuickTime/OBS] 录制，剪掉镜像拉取等待，保留验证通过的绿色输出。

### 2. 成功案例钩子：让第一个用户值得开口

- README「参与」区已有 success-story 表单；升级为**首 3 例反馈者进 README「早期采用者」名单 + 一条署名感谢推文**（用户执行，账号解锁后）。
- 在 Discussions 置顶一个「你卡在哪一步」模板帖——降低开口成本，负反馈也是反馈。

### 3. 定向 outreach：10 封手写邮件/私信 > 10 篇泛发帖

- 目标人群：正在给 **CLI 工具做 Linux 分发**的维护者（GitHub 搜索 `apt repository` / `.deb` release 的活跃项目）。
- 话术模板放 `outbox/2026-10-06-outreach.md`（自动化产出初稿）：一句话说明 + 演示 GIF + "你的项目我用 DeliverKit 打了个 deb，证据在此"。**先给价值，再求反馈。**
- **给代理的任务卡**：每周 5 个目标项目，逐个看 release 惯例后个性化开头两句，禁止群发同文。

## 二、渠道执行节奏（账号解锁后按此表走）

账号是当前唯一硬阻断（gates.md）：npm 已解决；**还缺 Show HN / r/mcp / X / V2EX / 掘金 / 知乎 / Smithery / Glama 共 8 类账号**。注册可由代理代持，但发帖账号需长期养号，建议实名+历史正常使用。

| 周 | 动作 | 前置 | 负责人 | KPI（见 metrics.md 链接规约） |
|---|---|---|---|---|
| W1 | 破局三招全部就位；Smithery/Glama 上架 | 演示 GIF；账号 | 代理 + 自动化 | Glama 评分出现；evidence/ 有 3 案例证据 |
| W2 | r/mcp 首发（美东上午）→ 48h 盯回复 | W1 完成 + 账号 | 用户或代理 | 帖子 upvote ≥ 5、站点/仓库 referral 出现 |
| W3 | Show HN（与 W2 错开，标题克制、正文第一人称讲 trade-off） | W2 复盘后 | 用户亲自（HN 信任真人） | 前端页 3+；外部 issue 破零 |
| W4 | X 串推（引用目录收录 + 首批反馈）；V2EX 分享创造 | 有可引用的社交证明 | 代理 | npm 周下载 ≥ 60（首轮基线的 1.2 倍） |

**判停规则**：任一渠道 2 次尝试后 referral 仍为 0 → 降级为"只收录不发帖"，资源移到下一渠道；北极星（30 天 3 例成功交付，至 2026-10-21）到期未达 → 按 goal.md 复盘流程重定，不盲目加渠道。

## 三、自动化每日为推广做的事（无需人工）

1. **KPI 账本**：每天 12:00 在 `docs/automation/kpi-log.md` 追加一行（npm 下载、stars/issues、渠道事件），趋势异常（如某发帖后 48h 无变化）会在当日汇报里点名。
2. **渠道状态巡检**：检查 awesome-mcp-servers PR #14195、mcp.so issue #4070 的动态；需要人回复时把**回复草稿**放进 `outbox/`。
3. **内容草稿箱**：迭代受阻或轻量日，产出 1 条渠道内容草稿（遵守 matrix.md 铁律：不夸大，Windows/macOS/鸿蒙口径为「契约先行、签名门槛待验证」）。
4. **outreach 目标清单**：每周从 KPI 与 GitHub 趋势里挑 5 个候选项目，写进 `outbox/YYYY-MM-DD-outreach.md` 供代理执行。

## 四、给代理的一次性交接清单（可直接转发）

1. 注册 8 类账号（见上），全部开启 2FA，凭据交用户保管，代理只留会话。
2. 按 matrix.md 渠道 5 完成 Smithery/Glama 上架（server.json 已在仓库根）。
3. 录制 3 个自证案例（脚本见本文件一.1）。
4. 按 W1-W5 节奏执行发帖，每次发帖后把链接回填 matrix.md 并通知用户。
5. 所有对外文案以仓库 `copy/` 为底稿，禁止宣称「全生态已验证」。
